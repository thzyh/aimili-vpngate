# AimiliVPN 有效节点池与 Fork 维护设计

## 1. 背景

当前部署使用 `Guli-Joy/aimili-vpngate`。服务每次从 VPNGate 官方 API 取得 CSV 后，按上游返回顺序截取 `MAX_SCAN_ROWS` 条，再对这些候选执行 TCP 预筛与 OpenVPN 精验。纽约低内存 VPS 将 `MAX_SCAN_ROWS` 设置为 `30`，实际检查得到 30 个候选中约 20 个有效、10 个无效；官方同一快照仍有 67 个本机尚未测试的候选。

现有实现会把无效节点继续保存在节点列表中。单纯删除后立即刷新并不能补充新节点，因为这些无效节点仍位于官方列表前 30 条，会被再次加入。

## 2. 目标

1. 在低内存 VPS 上维护一个最多 30 个、只展示已验证有效节点的节点池。
2. 保留仍然健康的有效节点，无效节点立即移出可用池并进入有限期冷却。
3. 当前 30 条不足时，继续向官方完整候选列表后部补测，直到有效池达到目标或没有未测试候选。
4. 所有循环都有明确停止条件，不因上游持续返回同一批无效节点而无限重试。
5. 通过用户 Fork 维护定制代码，并能持续合并原仓库更新。
6. 新 VPS 只部署经过验证并固定到提交哈希的定制版本。

## 3. 非目标

本阶段不实现“距离 VPS 最近节点优先”，也不改变主连接、多出口、3x-ui、代理转发或 UI 布局。最近节点排序属于后续独立改动，避免同时改变节点数量与路由选择两个行为。

本阶段不在生产 VPS 上直接修改 `/opt/aimilivpn`。生产迁移必须等代码测试通过，并单独执行备份、切换和回滚验证。

## 4. 仓库与分支模型

- 用户仓库：`thzyh/aimili-vpngate`，公开 Fork，继续遵守 GPL-3.0。
- `origin`：`https://github.com/thzyh/aimili-vpngate.git`。
- `upstream`：`https://github.com/Guli-Joy/aimili-vpngate.git`。
- `main`：仅快进同步 `upstream/main`，不承载用户定制代码。
- `custom`：实际开发和部署分支，从 `main` 合并上游更新。

上游同步流程：

```bash
git fetch upstream
git switch main
git merge --ff-only upstream/main
git push origin main
git switch custom
git merge main
```

如果 `custom` 与新上游发生冲突，只解决实际冲突文件并重新运行全部测试；不使用强制覆盖或重写共享分支历史。

## 5. 节点池数据模型

节点分为三个集合：

1. **有效池**：最近一次完整 OpenVPN 验证通过、允许 UI 和路由使用的节点。
2. **候选队列**：来自当前 VPNGate API 快照、尚未在本轮测试且不在冷却期的节点。
3. **失败冷却区**：验证失败的节点及失败原因、失败时间和冷却截止时间。

失败记录复用或兼容现有 `blacklist.json`，不永久删除节点身份。冷却结束后，如果该 IP 仍由 VPNGate 提供，可以在后续刷新周期重新测试。

`nodes.json` 只保存有效节点和当前活动节点。未通过验证的候选不进入可见节点池；已有有效节点一旦健康检查失败，也立即从可用池移出并进入冷却区。

## 6. 获取与补池流程

每次维护任务按以下顺序运行：

1. 获取一次 VPNGate 官方 API 快照，解析最多 300 条唯一候选。
2. 读取现有有效池和失败冷却区。
3. 保留当前仍健康的有效节点；活动连接节点在验证切换完成前受到保护，避免中断正在使用的连接。
4. 将不在有效池、不在本轮已测试集合且不在冷却期的节点放入候选队列。
5. 每批最多测试 10 个候选；OpenVPN 精验并发继续由 `OPENVPN_TEST_CONCURRENCY` 控制，纽约低内存部署保持为 `2`。
6. 每批测试后，把通过的节点加入有效池，把失败节点写入冷却区。
7. 有效池达到目标数量后立即停止，不继续消耗资源。
8. 候选队列耗尽后停止；等待下一次官方 API 刷新，不在同一快照内重复拉取。

推荐新增配置：

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| `TARGET_VALID_POOL_SIZE` | `30` | 期望保留的有效节点数 |
| `MAX_FETCH_ROWS` | `300` | 单次 API 快照最多解析的唯一候选数 |
| `NODE_TEST_BATCH_SIZE` | `10` | 每轮送入精验的候选数 |
| `PROBE_FAILURE_COOLDOWN_SECONDS` | `1800` | 失败节点冷却时间 |

现有 `MAX_SCAN_ROWS` 保留一个版本的兼容读取并输出弃用提示，但只在没有显式设置 `MAX_FETCH_ROWS` 时作为回退值。自动部署与纽约 VPS 迁移时必须删除原来的 `MAX_SCAN_ROWS=30`，明确写入 `MAX_FETCH_ROWS=300`、`TARGET_VALID_POOL_SIZE=30` 和 `NODE_TEST_BATCH_SIZE=10`，避免旧环境变量继续把候选来源截断为 30 条。

## 7. 停止条件与异常处理

维护任务满足任一条件即结束：

- 有效池达到 `TARGET_VALID_POOL_SIZE`；
- 当前 API 快照没有未测试候选；
- API 获取失败，继续保留已有有效节点；
- 服务收到停止信号；
- 已有维护任务持有互斥锁，本次请求直接返回“正在运行”。

同一个节点在同一快照内最多测试一次。失败节点不会因删除后重新读取 API 而在本轮再次进入候选队列。

API 获取失败、部分测试异常或地理信息富化失败均不得清空已有有效池。写入节点池时继续使用原项目的原子 JSON 写入方式，避免服务中断留下半写文件。

## 8. 有效节点保留与健康检查

- 有效节点在定期健康检查通过时继续保留。
- 节点一旦完整 OpenVPN 验证失败，立即从 UI 可用池移出并进入冷却。
- 当前活动节点由现有出口守护逻辑判断；只有真实出口失败达到现有阈值后才切换，避免单次抖动中断连接。
- 从 VPNGate 快照消失但仍处于活动且出口健康的节点允许短暂保留；不活动且从快照消失的节点在下一轮维护时移除。

## 9. 测试设计

新增纯标准库单元测试，不引入第三方 Python 依赖。至少覆盖：

1. 20 个有效、10 个失败、后续 67 个未测候选时，能够继续向后补池。
2. 达到 30 个有效节点后立即停止，不测试剩余候选。
3. 全部候选失败时能够结束，不无限循环。
4. 失败节点在同一快照内不会重复测试。
5. 冷却中的节点不进入候选队列，冷却到期后允许重新测试。
6. API 获取失败时保留现有有效池。
7. 活动节点不会在补池过程中被误删。
8. `OPENVPN_TEST_CONCURRENCY=2` 时批处理行为正确。

静态验证包括：

```bash
python3 -m py_compile vpngate_manager.py vpn_utils.py proxy_server.py
python3 -m unittest discover -s tests -v
bash -n install.sh
```

## 10. 部署版本固定

功能通过测试后，再修改 `aimili-3xui-simple-deploy`：

1. AimiliVPN 下载源改为 `thzyh/aimili-vpngate`。
2. 安装器支持明确的仓库、分支或提交参数。
3. 自动部署固定到 `custom` 上已验证的提交哈希，并校验 `install.sh` SHA-256。
4. 不从移动中的分支头直接部署生产环境。
5. 每次合并上游后先运行测试，再人工提升部署脚本中的固定提交。
6. 低内存 systemd 配置改用 `MAX_FETCH_ROWS=300` 和 `NODE_TEST_BATCH_SIZE=10`，并继续保留 `OPENVPN_TEST_CONCURRENCY=2`。

新 VPS 因而总是得到已验证版本；上游或 `custom` 分支出现新提交不会自动改变生产部署内容。

## 11. 生产迁移与回滚

当前纽约 VPS 不在本阶段自动迁移。后续迁移步骤为：

1. 备份 `/opt/aimilivpn/vpngate_data`、systemd 配置和当前提交。
2. 停止维护线程并确认当前服务状态。
3. 将 Git 远程切换到用户 Fork，检出已验证提交。
4. 保留 `vpngate_data`，重启服务。
5. 验证 UI、有效节点补池、主 SOCKS 出口、多出口和 3x-ui 数据流。
6. 失败时恢复原提交和备份配置。

未经端到端验证，不修改现有 VPS 的 Git 远程和运行版本。

## 12. 验收标准

- UI 节点池不再长期保留已验证失败节点。
- 当前有效节点不足目标值时，程序会测试官方列表后部候选。
- 达到目标或候选耗尽后维护任务确定结束。
- 失败节点不会在同一轮反复出现。
- 低内存配置下服务内存和并发保持受控。
- 上游 `main` 可以继续快进同步，`custom` 的差异可通过 GitHub 比较和普通 Git 合并审查。
- 新 VPS 部署脚本固定到用户 Fork 的已验证提交，而不是移动分支。
